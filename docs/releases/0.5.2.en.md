# Nelcota 0.5.2 — 2026-10-23

## A clearer operational workspace

- A graphite panel with orange actions, a compact navigation rail, contextual
  breadcrumbs and real project resource cards. Light mode and mobile navigation
  remain available.
- Pending confirmations stay visible, loading failures offer retry controls,
  and resource cards adapt to the available width. Keyboard focus, contrast and
  narrow-screen error feedback are improved.
- Enrolled host operators gain Server health, projects, backups and settings
  controls. Email and HTTPS webhook incident digests cover service health, disk,
  certificate expiry and overdue/failed backups. Delivery requires explicit
  operator approval; an entire VPS outage needs an independent heartbeat observer.
- External backups require HTTPS and verified database, files and encrypted
  recovery configuration before reporting success or pruning local history.
- Update `ctutils` to 0.4.4 for RUSTSEC-2026-0385.

## Upgrade safely

The 0.5.1 → 0.5.2 update retains internal schema **V16** and existing HTTP/SDK
contracts. Keep and restore-test a paired database/file backup, retain the prior
binary/image and allow a maintenance window. Upgrades from 0.4.0 still apply
V14–V16. Review [backup provider requirements](../backup.md) before updating:
external providers must support AES256 encryption for recovery configuration.

Use matching CLI/controller versions and explicit host enrollment. Project panel
credentials do not grant host authority. Rehearse independent heartbeat alerts
before relying on them. PITR still requires explicit `pitr recover` while fenced.

Verify checksums, build attestations, both OCI architectures and the signed
`update-manifest.json` for the exact source. Panel update installation remains
behind the [VPS acceptance gate](../panel-updates.md#enablement-and-acceptance-evidence);
a release does not enable installation automatically. No new endurance or
production-host certification is claimed.

Updating the server does not update client SDKs. TypeScript 0.2.1 and Rust 0.1.4
remain independently distributed packages. See [versions and upgrades](README.md).
