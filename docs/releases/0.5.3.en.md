# Nelcota 0.5.3 — 2026-10-23

## A consistent panel and operator console

- Official SVG logos replace the mascot. Both panels retain Manrope and graphite
  surfaces, with cobalt primary buttons, neutral selections and clearer icons.
- Expandable sidebar subcategories group database tools, users, webhooks and API
  sections. The mobile menu uses the same hierarchy. Contextual table views,
  filters and example languages remain beside their content.
- The operator console brings server areas into its sidebar and clarifies release
  comparison, approval, recovery and history. Existing operator authentication,
  password confirmations, operation guards and installation gates remain intact.
- The empty table editor has one primary creation action. Loading, catalog errors
  and no-match searches remain distinct. Re-selecting an API section scrolls to
  it again without resetting position when changing example options.
- Mailer, storage and database diagnostics retain useful typed context without
  opaque provider messages or identifying paths. Request diagnostics are bounded
  and use route templates while retaining request correlation.

## Upgrade safely

The 0.5.2 → 0.5.3 update retains internal schema **V16**, configuration formats
and HTTP/SDK contracts. Take and restore-test a paired database/file backup,
keep the prior binary/image and allow a maintenance window. Upgrades from 0.4.0
still apply V14–V16. Follow [backup](../backup.md) and [deployment](../deploy.md).

Update both the CLI and application/controller artifacts to receive the new
interfaces. Project panel credentials do not grant host authority. An enrolled
controller still requires the existing [VPS acceptance gate](../panel-updates.md#enablement-and-acceptance-evidence)
before installing updates; publishing this release does not enable it. A PITR
restore fence still requires explicit `pitr recover`.

Verify binary checksums, build attestations, both OCI architectures and the
signed `update-manifest.json` for the exact release source. Local acceptance
and CI do not establish production VPS, public TLS or off-host recovery evidence.

Updating the server does not update client SDKs. TypeScript 0.2.1 and Rust 0.1.4
retain independent release cycles; this server release does not publish them.
