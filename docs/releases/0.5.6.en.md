# Nelcota 0.5.6 — 2026-10-27

## Panel passwords and the host controller

- Panel and `nelcota dev` passwords no longer use characters that look alike
  when copied by eye (0/O, 1/l/I). They stay 20 random characters, about 116
  bits. Each printed password comes with the exact command that prints a new
  one: `nelcota -C <host> admin-password`.
- A failed backup destination, SMTP or alert test in the host controller now
  ends `failed`. Wrong S3 keys used to leave the host waiting for attention and
  block every later operation, including the one that would fix the keys, until
  it was repaired over SSH. An interrupted test still waits for recovery.
- Saving a backup destination in the controller does not test it: run **Test
  backup** after saving.

## A one-command VPS setup that configures everything

The installer is served from `main`, so these changes already apply to any
version it installs:

- The firewall is on by default (SSH, 80 and 443; `--no-firewall` leaves it
  off). An already active firewalld or ufw only gets HTTP and HTTPS added.
- Automatic security updates on Debian/Ubuntu, and a 2 GB swap file below 2 GB
  of RAM without swap.
- `--yes` skips every `nelcota init` question, such as the S3 backup one.
- The script runs nothing until it has fully downloaded, compares the binary
  with the published SHA-256 itself, replaces it atomically after checking the
  version, starts Docker before `init`, waits for the apt lock on fresh images
  and refuses invalid settings before changing anything. Unsupported systems
  stop early, and translated system output no longer breaks it.

## Upgrade and verification

The **0.5.5 → 0.5.6** patch adds no migration: internal schema remains **V16**.
Take and restore-test a paired database/file backup, preserve the previous
binary/image and follow [backup](../backup.md) and [deployment](../deploy.md).
Install the matching CLI before upgrading the application/controller.

A controller test job already stuck by 0.5.5 keeps its record: fix the keys in
`host.env` over SSH, then recover it from the panel. Passwords generated before
this release keep working.

Verify binary checksums, provenance, the amd64/arm64 OCI index and the signed
`update-manifest.json` against the exact source before controlled installation.
Existing host enrollment, operator authentication, recovery and VPS acceptance
gates stay in force.

SDK releases are independent: TypeScript **0.2.5**, Rust **0.1.7**, Next.js
**0.1.2** and SSR **0.1.0** keep their own package lifecycle. Updating this
server does not update client applications.

## Evidence and remaining scope

Release acceptance and upgrade/restore evidence must identify the tested binary
and source; see [the handoff](../onboarding/release.md). This patch does not
claim a new sustained-load certification, public TLS/firewall or off-host/cloud
recovery validation.
