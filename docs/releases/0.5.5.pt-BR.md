# Nelcota 0.5.5 — 2026-10-27

## Requisições de saída e uploads mais seguros

- Os webhooks de alerta do host passam a usar a mesma política de endereços
  públicos dos webhooks de projeto. Os destinos de alerta deixam de aceitar o
  relay 6to4, o IPv6 de descarte, os blocos IPv6 da IETF e de documentação e
  qualquer endereço fora de 2000::/3. O gerenciamento do host mantém uma
  checagem mais permissiva para os servidores do próprio operador, mas recusa
  240.0.0.0/4 e as formas IPv6 que embutem um endereço IPv4.
- Endpoints de alerta escritos como IPv6 literal agora recebem as entregas em
  vez de falhar.
- Um tipo de imagem, áudio ou vídeo declarado só é aceito quando os bytes o
  confirmam; os outros uploads dessas famílias são gravados como
  `application/octet-stream` e baixados em vez de exibidos na página.
- Editar uma política no painel mantém os papéis personalizados, então ela não é
  mais ampliada para `TO PUBLIC`. Requisições de escrita ao painel com `Origin`
  inválido ou `Sec-Fetch-Site: same-site` são recusadas.
- O `PUT /auth/v1/user` confere se a sessão continua ativa antes de verificar o
  `current_password`, e o `init --firewall` mantém abertas as portas SSH
  personalizadas.

## Um painel mais rápido

- A tela de entrada baixa cerca de 31% menos. Cada idioma e cada guia carregam
  sob demanda, e um navegador que já estava conectado chega aos dados em 4
  requisições sequenciais em vez de 6. O servidor envia os arquivos já
  comprimidos com brotli a partir do binário, com revalidação por ETag nas
  páginas HTML de entrada.
- Resultados SQL com mais de 200 linhas são virtualizados: um resultado de 1000
  linhas aparece em cerca de 0,2 s em vez de 2 s. As grades e as prévias JSON
  fazem menos trabalho por célula, e as prévias JSON mantêm todos os dígitos.
- Uma seção "Contexto para IA" na página API monta um documento no estilo
  `llms.txt` para assistentes de código, sem segredos.
- Os consoles do host e de atualizações validam as respostas do controlador com
  validadores gerados a partir do Rust. Os tamanhos do host usam unidades
  binárias no formato numérico de quem lê.

## Outras correções

- Contas OAuth vinculadas são confirmadas quando o provedor verifica o e-mail, e
  os parâmetros `code`/`error` antigos são removidos do `redirect_to`.
- O catálogo do schema carrega num único snapshot; filtros e aliases malformados
  retornam `400`, e um bucket apagado durante um upload retorna `404`.
- Tokens de uso único e estados de fluxo OAuth expirados são removidos. O e-mail
  do operador é validado no cadastro, e um panic da CLI restaura o eco do
  terminal.

## Atualização e verificação

A atualização **0.5.4 → 0.5.5** não adiciona migrations: o schema segue em **V16**.
Atualizações de 0.4.0 ainda aplicam V14–V16 e exigem uma janela de manutenção
medida. Faça e teste a restauração do backup pareado de banco e arquivos,
preserve o binário/imagem anterior e siga [backup](../backup.md) e
[implantação](../deploy.md). Instale a CLI correspondente antes de atualizar
a aplicação/controlador.

Revise os endpoints de alerta que apontam para as faixas agora recusadas e os
uploads que dependiam de um subtipo de mídia não verificado ser exibido na
página. O binário fica cerca de 2 MB maior porque embute as cópias brotli do
painel.

Confira checksums, proveniência, o índice OCI amd64/arm64 e o
`update-manifest.json` assinado para o código exato antes da instalação
controlada. Cadastro do host, autenticação do operador, recuperação e validação
da VPS continuam em vigor.

Os SDKs mantêm ciclos independentes: TypeScript **0.2.4**, Rust **0.1.7** e
Next.js **0.1.2**. A leitura de JSON mais rápida do SDK TypeScript ainda não foi
publicada. Atualizar o servidor não atualiza os aplicativos consumidores.

## Evidências e limites

A aceitação da release e o ensaio de upgrade/restauração devem identificar
binário e código testados; consulte [a preparação](../onboarding/release.md).
Este patch não certifica uma nova endurance, TLS/firewall público ou
recuperação externa/em nuvem.
