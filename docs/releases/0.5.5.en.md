# Nelcota 0.5.5 — 2026-10-27

## Safer outbound requests and uploads

- Check host alert webhooks with the same public-address policy as project
  webhooks. Alert destinations no longer accept the 6to4 relay, discard-only
  IPv6, the IETF and documentation IPv6 blocks or anything outside 2000::/3.
  Host management keeps a looser check for the operator's own servers but
  refuses 240.0.0.0/4 and IPv6 forms that embed an IPv4 address.
- Alert endpoints written as an IPv6 literal now deliver instead of failing.
- Trust a declared image, audio or video type only when the bytes confirm it;
  other uploads in those families are stored as `application/octet-stream` and
  downloaded instead of shown inline.
- Keep custom roles when a policy is edited in the panel, so it is no longer
  widened to `TO PUBLIC`. Refuse state-changing admin requests with an invalid
  `Origin` or `Sec-Fetch-Site: same-site`.
- Check that the session is still active before `PUT /auth/v1/user` verifies
  `current_password`, and keep custom SSH ports open with `init --firewall`.

## A faster panel

- The sign-in screen downloads about 31% less. Each language and guide loads on
  demand, and a returning browser reaches its data in 4 sequential requests
  instead of 6. The server sends brotli-precompressed assets from the binary,
  with ETag revalidation for HTML entry points.
- SQL results over 200 rows are virtualized: a 1000-row result renders in about
  0.2 s instead of 2 s. Grids and JSON previews do less work per cell, and JSON
  previews keep every digit.
- A "Context for AI" section on the API page builds an `llms.txt`-style
  document for coding assistants, without secrets.
- The host and updates consoles validate controller replies with validators
  generated from Rust. Host sizes use binary units in the reader's number format.

## Other fixes

- Linked OAuth accounts are confirmed once the provider verifies the email, and
  stale `code`/`error` parameters are removed from `redirect_to`.
- The schema catalog loads in one snapshot; malformed filters and aliases
  return `400`, and a bucket deleted during an upload returns `404`.
- Expired one-time tokens and OAuth flow states are pruned. Operator emails are
  validated at enrollment, and a CLI panic restores terminal echo.

## Upgrade and verification

The **0.5.4 → 0.5.5** patch adds no migration: internal schema remains **V16**.
Upgrades from 0.4.0 still apply V14–V16 and need a measured maintenance window.
Take and restore-test a paired database/file backup, preserve the previous
binary/image and follow [backup](../backup.md) and [deployment](../deploy.md).
Install the matching CLI before upgrading the application/controller.

Review alert endpoints that point at the newly refused ranges, and uploads that
relied on an unverified media subtype being shown inline. The binary is about
2 MB larger because it embeds brotli copies of the panel.

Verify binary checksums, provenance, the amd64/arm64 OCI index and the signed
`update-manifest.json` against the exact source before controlled installation.
Existing host enrollment, operator authentication, recovery and VPS acceptance
gates stay in force.

SDK releases are independent: TypeScript **0.2.4**, Rust **0.1.7** and Next.js
**0.1.2** keep their own package lifecycle. The faster TypeScript JSON parse is
not published yet. Updating this server does not update client applications.

## Evidence and remaining scope

Release acceptance and upgrade/restore evidence must identify the tested binary
and source; see [the handoff](../onboarding/release.md). This patch does not
claim a new sustained-load certification, public TLS/firewall or off-host/cloud
recovery validation.
