# Nelcota 0.5.1 — 2026-10-21

This patch consolidates installation checks, authentication hardening and panel
reliability fixes. Confirm artifacts and signed readiness on the
[official release page](https://github.com/Nelcota/Nelcota/releases/tag/v0.5.1).

## Highlights

- Installation refuses missing privileges, inactive Linux backup scheduling and
  unavailable or failing requested UFW operations before writing host credentials.
  Install and activate the documented scheduler, and allow the actual SSH port
  before enabling the firewall. See [deployment prerequisites](../deploy.md).
- Auth email requires implicit TLS or mandatory STARTTLS. Plain or opportunistic
  SMTP and ambiguous URL options are refused. Refresh retry grace cannot extend
  past token expiry; auth responses disable caching while public JWKS caching
  remains unchanged.
- Update TLS certificate verification and root-store dependencies to their patched
  versions, addressing RUSTSEC-2026-0381, RUSTSEC-2026-0382 and RUSTSEC-2026-0383.
- Panel forms preserve drafts during navigation/history changes. Dialogs, password
  entry, account/project controls and status contrast work better on small screens
  and with enlarged text. Editing another bucket setting preserves its exact byte
  limit, including values smaller than 0.01 MiB.
- Ordinary panel JSON requests have a 60-second deadline, including response reads.
  On timeout controls are released and drafts remain. A write may already have
  completed: refresh the data before a manual retry. Writes are not automatically
  repeated, and logout/login ordering remains serialized.
- Overflowing table/user page offsets return a validation error before database
  work. Update-controller status rejects non-boolean `host_busy` values.

## Upgrade and compatibility

The **0.5.0 → 0.5.1** patch adds no internal migration: the schema remains at
**V16**. Existing supported HTTP/SDK contracts, configuration formats and CLI
flags remain unchanged. Review SMTP settings and host prerequisites above;
unsupported insecure mail settings now fail validation.

Keep and restore-test a paired database/file backup before updating. Retain the
previous executable/image and allow a maintenance window. Upgrades from **0.4.0**
still apply V14–V16 and may rewrite large storage metadata tables; rehearse on a
representative staging copy. Follow the [release handoff](../onboarding/release.md).

PITR retains its startup fence and explicit `pitr recover` requirement. Plain `up`
does not clear a restore fence. Existing layout restrictions and the documented
account-wide rate-limit trade-off remain unchanged.

The TypeScript and Rust SDKs have independent package versions. Updating the
server does not update client dependencies or publish new SDK packages. See the
[version and upgrade guide](README.md).

## Artifact verification and panel updates

Verify binary SHA-256 checksums and build attestations, both OCI architectures and
the signed `update-manifest.json` for the exact release source. Readiness requires
successful main CI for that source; a source tag alone is insufficient.

Publishing this release does not enable installations through the panel. Keep
`enable_installation: false` until the exact controller binary completes the
[VPS acceptance matrix](../panel-updates.md#enablement-and-acceptance-evidence).
Local Notes/browser and backup/restore checks do not certify public TLS, real
power loss or off-host recovery. No new stress/endurance certification is claimed.
