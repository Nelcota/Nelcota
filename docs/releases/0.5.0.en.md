# Nelcota 0.5.0 — 2026-10-19

Server 0.5.0 is [published](https://github.com/Nelcota/Nelcota/releases/tag/v0.5.0).
Verify checksums/provenance and readiness for the selected artifacts before
installation. The bullets below retain the 0.5.0 release scope; current SDK patch
versions and upgrade instructions are in the [version guide](README.md).

- PITR errors that may have changed data retain a durable startup fence across
  service, Docker daemon and host restarts. Plain `up` is no longer recovery:
  use `pitr recover` or a verified successful restore. Docker restore temporarily
  rewrites Compose and removes containers, never volumes. Default PGDATA and
  exact supported PostgreSQL command/tuning profiles are required; custom
  entrypoints, commands, data-directory/config-file overrides and older app
  images are refused. Recovery may install `amcheck` in `pg_catalog`.
- Preserve native project/host ownership, database-cluster isolation and working
  directories; release SQL/export/catalog/client resource owners on cancellation.
  Keep paired database/file backups and rehearse restore before upgrading.
- Enforce optional JWT `nbf`/`iat` with 30-second leeway; `iss`/`aud` remain
  informative. Bound account passwords before DB/hash admission and redact
  authentication adapter diagnostics without lowering Argon2 strength.
- Login retains hard IP/account-source quotas. Account-wide pressure becomes
  progressive delay capped at two seconds. Distributed sources can exceed the
  former aggregate hard ceiling; this is not an account-wide brute-force cap.
  Use trusted ingress abuse controls and the documented operator recovery path
  when SMTP is disabled. Worker admission and overload responses are unchanged.
- Harden session invalidation.
- Persist panel SSO replay protection.
- Optional host project management/update controls require explicit enrollment,
  scoped authorization, visual confirmation and the documented VPS acceptance
  gates. No production update/deploy is enabled by preparing this release.
- Upgrade from 0.4.0 applies V14/V15 user and storage listing indexes and V16
  durable panel SSO redemption receipts. Take and test a paired database/file
  backup before upgrading; allow a maintenance window for large metadata tables.
  V16 is not part of the standalone auth migration selection. A manual downgrade
  requires the compatible database and paired file snapshot.
- TypeScript SDK 0.2.0 is a separately published package: native browser auth needs
  IndexedDB, all tabs must reload on upgrade, generated numeric types widen to
  `number | string`, and arrays may include null elements. Regenerate schema
  types. Session/PKCE cancellation and sign-out cleanup corrections require the
  new client package. Rust SDK 0.1.3 keeps Rust 1.88+ and server 0.3.0+ support.
  A server update does not update installed SDKs. TypeScript 0.2.0 and Rust 0.1.3
  are the independently published SDK baselines for this server release.

Before installation, verify binary checksums/provenance, the OCI index and release
readiness for the exact source. Existing access JWTs remain valid until expiry.
Real OAuth/mail, public TLS and deployment-specific restore/acceptance gates are
not certified by the local auth review. Historical G05 stress evidence remains
bound to its original artifact and is not a new 0.5.0 soak.
