# Nelcota 0.5.4 — 2026-10-25

## File integrity and stable sessions

- Keep immutable file bytes when the database commit response is lost; check the
  current object before retrying a write with an unknown outcome.
- Bind automatic file collection to durable database ownership. Ambiguous stores
  retain their bytes and collection remains quarantined across process restarts.
  Use a separate disk root or S3 bucket per independent metadata database.
  Only application instances on the same writable database may share a target;
  independent physical copies, lagging replicas and older writers require
  separate targets. Preserve ownership/quarantine markers during investigation.
- Acquire refresh-session ownership before token rows, avoiding deadlocks between
  retries and successors. Reuse fixed query plans. Oversized present refresh
  tokens return `400 invalid_grant`; missing/empty validation stays separate.

## A clearer panel and installation

- Refresh the login, saved-theme startup, progress/offline feedback, confirmations
  for privileged tokens/public buckets, webhook feedback and mobile database tools.
- Preserve literal PostgreSQL column/type names in filtering, sorting, row editing
  and OpenAPI presentation. Preserve early calendar years, reject normalized
  invalid dates and bound deeply nested JSON indentation.
- Restore keyboard access to read-only scroll regions and give code samples
  supported accessible names. Retain official branding and Manrope typography
  with consistent positive and neutral feedback.
- Support one-command VPS preparation through installer arguments and the guarded
  `upgrade --without-controller` fallback. Host authority and recovery checks
  remain required; this release does not activate panel installation by itself.
- Refresh Rust 1.99.1, compatible dependencies, Oxlint 1.89.0 and pinned Actions.
  Exclude private/generated files from Docker contexts. The backend still needs
  no Node runtime, and the Rust SDK retains Rust 1.88 support.

## Upgrade and verification

The **0.5.3 → 0.5.4** patch adds no migration: internal schema remains **V16**.
Upgrades from 0.4.0 still apply V14–V16 and need a measured maintenance window.
Take and restore-test a paired database/file backup, preserve the previous
binary/image and follow [backup](../backup.md) and [deployment](../deploy.md).
Install the matching CLI before upgrading the application/controller.

PITR fences still require explicit `pitr recover`. Existing host enrollment,
operator authentication, recovery and VPS acceptance gates stay in force.
Verify binary checksums, provenance, the amd64/arm64 OCI index and the signed
`update-manifest.json` against the exact source before controlled installation.

SDK releases are independent: TypeScript **0.2.3**, Rust **0.1.6** and Next.js
**0.1.1** keep their own package lifecycle. Updating this server does not update
client applications or publish those packages.

## Evidence and remaining scope

Release acceptance and upgrade/restore evidence must identify the tested binary
and source. See [the handoff](../onboarding/release.md) and
[the audit record](../goals/full-project-audit-20261025.md). Historical performance
measurements keep their original artifact identity. The earlier 664/s disk profile
remains failed at its documented retained-history ceiling; the final local S3
hour was interrupted by the environment. No gate or limit was relaxed.
This patch does not claim a new sustained-load certification, real power-loss/
VM recovery, public TLS/firewall or off-host/cloud recovery validation. Thirteen
contrast observations and screen-reader verification still need manual review.
